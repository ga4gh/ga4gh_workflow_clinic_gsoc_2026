# Workflow Doctor

The **Workflow Doctor** is an automated multi-layer remediation engine for repairing defects in scientific workflow pipelines (such as Nextflow and Snakemake). It analyzes diagnostic findings generated by `workflow-clinic examine` and applies targeted, syntax-verified fixes directly to your source files.

---

## 🏗️ 3-Tier Strategy Cascade

The Doctor engine resolves findings using a prioritized **3-Layer Cascade**:

| Layer | Strategy | Speed | Scope / Purpose | Rules Handled |
| :--- | :--- | :--- | :--- | :--- |
| **Layer 1** | **AST-First Injections** | Instant (Deterministic) | Syntax tree directive injection and modification with exact indentation. | `W001` (Containers), `W002` (CPU & Memory Limits) |
| **Layer 2** | **Regex Pattern Matching** | Fast (Heuristic) | Pattern-based parameterization, credential masking, and scoped string replacements. | `W003` (Hardcoded Absolute Paths), `W004` (Hardcoded Credentials) |
| **Layer 3** | **LLM-Powered AI Repair** | Contextual | Dynamic AI code generation via LiteLLM with AST syntax verification. | `AI001` (AI Critic Findings & Complex Semantic Patches) |

The execution cascade ensures that fast, deterministic rules are resolved first. If a rule cannot be patched at Layer 1 or 2, the runner falls back to higher tiers.

## 💻 CLI Usage Guide

The `workflow-clinic fix` command operates on local workflow files, directories, or pre-generated `diagnosis.json` reports.

### 1. Interactive Terminal Remediation

By default, running `workflow-clinic fix` on an interactive terminal displays an interactive selection menu grouped by category domain:

```bash
# Run interactive doctor on current repository
workflow-clinic fix

# Run doctor on a specific workflow file or diagnosis report
workflow-clinic fix path/to/pipeline.nf
workflow-clinic fix diagnosis.json
```

### 2. Batch Non-Interactive Mode (`--all` / `-y`)

To apply all available fixes non-interactively (e.g. in CI/CD pipelines or automated batch scripts):

```bash
workflow-clinic fix --all
# or
workflow-clinic fix -y
```

### 3. Dry-Run Mode (`--dry-run`)

Preview the proposed code modifications without writing changes to disk:

```bash
workflow-clinic fix --dry-run
```

The Doctor renders a terminal diff showing exact lines added, modified, or removed.

### 4. The 3 Remediation Modes

| Command | Mode | Execution Strategy | API Key Required? |
| :--- | :--- | :--- | :--- |
| `workflow-clinic fix` | **Fully Offline** | Layer 1 AST (`W001`, `W002`) + Layer 2 Regex (`W003`, `W004`). Instant, zero-cost, 100% deterministic. | ❌ No |
| `workflow-clinic fix --enhance` | **Hybrid Cascade** | AI Critic finds subtle issues (`AI001`–`AI003`). AST/Regex solves `W00x`, AI solves `AI00x`. | ✅ Yes |
| `workflow-clinic fix --ai-only` | **All with AI** | Routes **every finding** (`W001`–`W004` & `AI001`+) directly to `AIFixer` to generate context-aware AI solutions. | ✅ Yes |

```bash
# 1. Run fully offline (deterministic AST + Regex only)
workflow-clinic fix

# 2. Run hybrid cascade (AST/Regex for W00x + AI for AI00x)
workflow-clinic fix --enhance

# 3. Force all issues to be solved using AI
workflow-clinic fix --ai-only
```

### 5. Rule Filtering (`--rule` / `-r`)

Target specific diagnostic rules:

```bash
# Only fix container pinning and resource limit violations
workflow-clinic fix -r W001 -r W002 --all
```

### 6. GitHub Integration (`--repo` & `--token`)

If you are triaging issues across a GitHub repository, pass credentials to synchronize with open issue fingerprints:

```bash
workflow-clinic fix --repo owner/my-pipeline --token ghp_xxxx
```

## 🐍 Python API Usage

You can invoke the Doctor engine programmatically within Python:

```python
from pathlib import Path
from workflow_clinic.doctor.runner import DoctorRunner
from workflow_clinic.models.diagnosis import Finding

# 1. Prepare findings to resolve
findings = [
    Finding(
        rule_id="W001",
        severity="error",
        message="Process 'FASTQC' has no container defined.",
        file_path="main.nf",
        process_name="FASTQC",
    ),
    Finding(
        rule_id="W003",
        severity="warning",
        message="Process 'FASTQC' contains hardcoded path: '/data/genomes/hg38.fa'",
        file_path="main.nf",
        process_name="FASTQC",
    ),
    Finding(
        rule_id="AI001",
        severity="info",
        message="Process 'FASTQC' should use modern Nextflow syntax.",
        file_path="main.nf",
        process_name="FASTQC",
    ),
]

# 2. Initialize runner and execute cascade
runner = DoctorRunner()
session = runner.run(findings, root_dir=Path.cwd(), dry_run=False)

# 3. Inspect results
for applied in session.applied_proposals:
    print(f"Applied {applied.proposal.rule_id} via {applied.proposal.strategy_layer.name}")
```

## 🧩 Registering Custom Fixers

Developers can register new rule fixers into the Doctor registry using the `@FixerRegistry.register` decorator:

```python
from workflow_clinic.doctor.base import BaseFixer, FixerRegistry
from workflow_clinic.models.fix import FixProposal, FixStrategyLayer

@FixerRegistry.register
class MyCustomFixer(BaseFixer):
    rule_id = "W999"
    strategy_layer = FixStrategyLayer.LAYER1_AST

    def generate_proposal(self, finding, bundle=None, source_code=None):
        # 1. Calculate the fix patch
        proposed_code = source_code.replace("bad_code", "good_code")
        
        # 2. Return a FixProposal
        return FixProposal(
            finding_id=finding.id,
            rule_id=self.rule_id,
            category=finding.category,
            target_file=finding.file_path,
            original_snippet=source_code,
            proposed_snippet=proposed_code,
            explanation="Fixed custom violation W999.",
            strategy_layer=self.strategy_layer,
        )
```
